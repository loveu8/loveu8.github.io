## 1. 這個頁面要解決什麼問題

Noosa 頁是「照時間走的行程」；烘焙頁是「從清單挑店、去之前快速看要點什麼」。使用情境有三個：

1. **出門前挑店**：今天想吃可頌，哪幾家是 A 級？在哪一區？
2. **到店前確認**：這家店大家點什麼？今天有沒有開？要不要早點去？
3. **吃完後記錄**：試吃日期、花費、評分（目前 csv 裡都是空的）

所以重點是**篩選＋卡片**，不是時間軸。

## 3. 店家卡片內容

由上到下，依「到店前最需要知道的」排序：

| 區塊 | 來源欄位 | 呈現方式 |
|---|---|---|
| 優先級 | `優先級` | 小徽章 A／B／C；用文字，不只靠顏色 |
| 店名、區域 | `店家`、`區域` | 店名粗體；區域放副標 |
| Google 評分 | QA.md 第二輪 | ★4.8（1,530）；標註「2026-10 快照」 |
| 分類 | `分類` | 中性 chip，不另外配色 |
| **大家推薦前三名** | `大家推薦前三名` ＋ TOP3.md 次數 | 卡片主體。🥇🥈🥉 ＋ 中文名 ＋ 英文名 ＋「N 則提到」；低信心標「資料少」 |
| 我想吃的 | `目標品項` | 跟前三名不同時才顯示，避免重複 |
| 提醒 | `試吃備註及訪前提醒` | 琥珀色小區塊（公休、售完、預訂） |
| 地圖 | `地址` | 📍 地址 pill（預覽地圖）＋ ↗ Maps pill（開 Google Maps） |
| 試吃紀錄 | `試吃日期`～`平均分數` | 有填才顯示；沒填就不出現 |
| 資料來源 | `查核來源網址` | 卡片底部小字連結 |

**配色依 DESIGN.md 的語意**：珊瑚色＝美食（前三名的強調）、藍色＝地圖按鈕、琥珀色＝提醒、中性＝分類 chip。不替 7 個分類各配一個顏色，避免頁面變花。

## 4. 地圖

- 沿用 Noosa 的免 API key 嵌入方式：點 📍 時地圖顯示那一家店。
- **限制**：這種嵌入一次只能顯示一個地點，**沒辦法把 24 家同時標在地圖上**。
- 預設畫面：顯示布里斯本市中心，或目前分類的第一家店。
- 如果想要「所有店一次標在地圖上」，要另外在 Google My Maps 手動建圖層再嵌入（見第 7 節）。

## 5. 資料怎麼進到網頁

依 `AGENTS.md`：頁面要能用 `file://` 直接打開，所以**不能用 `fetch()` 讀 csv**。

建議流程：

```
bakery.csv ──┐
TOP3.md 數字 ─┼─▶ build_data.py ─▶ data.js（var BAKERY_DATA = {...}）─▶ index.html 用 <script> 載入
QA.md 評分 ──┘
```

- `bakery.csv` 仍是唯一的主資料；改 csv 後重跑腳本就會更新網頁。
- csv 目前缺網頁要用的幾個欄位：
  - Google 評分、評論數（現在只在 QA.md）
  - 前三名各自的提及次數（現在只在 TOP3.md）
  - 前三名的信心度
- 建議**把這三個欄位補進 csv**，腳本只讀 csv 一個來源，不去解析 markdown。
